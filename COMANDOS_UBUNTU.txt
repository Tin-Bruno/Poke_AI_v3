COMANDOS GIT BASH - POKE_AI_V3
==============================

1) Preparar e ativar o ambiente virtual
---------------------------------------

Abra o Git Bash na pasta do projeto:

cd "/c/Users/bruno/OneDrive/Documentos/Poke_AI_v3"

Crie e ative o ambiente virtual no Windows/Git Bash:

py -3.11 -m venv .venv
source .venv/Scripts/activate
python --version
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
mkdir -p roms states models logs runs

Depois de ativar o ambiente, todos os comandos abaixo usam `python`.
Se abrir um Git Bash novo, ative de novo com:

source .venv/Scripts/activate


2) Validar o projeto
--------------------

python -m unittest discover -s tests -v

python -m py_compile project_config.py envs/pokemon_red_env.py envs/freeplay_env.py envs/step_handler.py envs/success_conditions.py memory/ram_map.py phases/phase_config.py rewards/base.py rewards/registry.py rewards/target_position_reward.py rewards/target_map_reward.py rewards/new_map_reward.py rewards/dialog_reward.py rewards/battle_reward.py rewards/waypoint_reward.py rewards/party_reward.py rewards/freeplay_reward.py scripts/train_phase.py scripts/eval_phase.py scripts/eval_sequence.py scripts/train_freeplay.py scripts/eval_freeplay.py scripts/test_env.py scripts/view_ram.py scripts/find_phase_path.py scripts/manual_control.py scripts/test_rom.py tests/test_env_config.py tests/test_rewards.py tests/test_success_conditions.py

python -m py_compile scripts/benchmark_env.py scripts/summarize_trace.py


Regra dos botoes nas fases:

B = passar dialogo/menu.
A = interagir com objeto/NPC no mundo.
A+B = eventos que precisam confirmar fala/interacao, como a phase4 do Oak.


3) Ver RAM de uma fase/state
----------------------------

python scripts/view_ram.py --phase phase1 --window null

python scripts/view_ram.py --phase phase2 --window null


4) Testar ambiente sem treinar
------------------------------

python scripts/test_env.py --phase phase1 --steps 40 --window null --observation-mode coords

python scripts/test_env.py --phase phase2 --steps 40 --window null --observation-mode coords

Testar sequencia sem sobrescrever states oficiais.
Use auto para o script escolher coords/ram conforme cada modelo:

python scripts/eval_sequence.py --through phase8 --window null --observation-mode auto --steps 3000


5) Modelo: treinar uma phase
----------------------------

Exemplo com phase1:
O agente comeca no quarto, usa observacao coords e aprende a sair para o proximo mapa.
Quando passar, salve o state da phase2.

Treino rapido/headless:

python scripts/train_phase.py --phase phase1 --timesteps 20000 --observation-mode coords --window null

Treino vendo a tela:

python scripts/train_phase.py --phase phase1 --timesteps 20000 --observation-mode coords --window SDL2 --n-envs 1 --vec-env dummy

Durante o treino, aperte q no terminal para interromper.
Quando o treino e interrompido, ele salva sem sobrescrever o modelo principal:

models/phase1_interrompido.zip

Treino com parametros iguais ao projeto v2:

python scripts/train_phase.py --phase phase1 --timesteps 20000 --observation-mode coords --window null --batch-size 64 --gamma 0.95 --n-epochs 10 --learning-rate 0.0003 --ent-coef 0.0


6) Modelo: avaliar e salvar state
---------------------------------

Avaliar rapido/headless:

python scripts/eval_phase.py --phase phase1 --window null --observation-mode coords --steps 400

Avaliar vendo a tela devagar:

python scripts/eval_phase.py --phase phase1 --window SDL2 --observation-mode coords --delay 0.3

Durante a avaliacao, aperte q no terminal para parar e fechar o PyBoy.

Salvar o state da phase2 quando a phase1 passar:

python scripts/eval_phase.py --phase phase1 --window SDL2 --observation-mode coords --delay 0.3 --save-success-state states/phase2_start.state

Salvar o state da phase2 headless:

python scripts/eval_phase.py --phase phase1 --window null --observation-mode coords --steps 400 --save-success-state states/phase2_start.state

python scripts/find_phase_path.py --phase phase1 --max-depth 80

python scripts/find_phase_path.py --phase phase2 --max-depth 80

9) Treinar mais rapido com varios PyBoys
-----------------------------------------

Use um unico PPO com varios ambientes, em vez de varios PPOs escrevendo no mesmo modelo.

Exemplo com 6 PyBoys em paralelo:

python scripts/train_phase.py --phase phase1 --timesteps 100000 --observation-mode coords --window null --n-envs 6 --vec-env subproc

Para ver a tela, use somente 1 ambiente:

python scripts/train_phase.py --phase phase1 --timesteps 20000 --observation-mode coords --window SDL2 --n-envs 1 --vec-env dummy


10) Freeplay depois da Rota 1
-----------------------------

Salvar um state para o freeplay quando a phase9 passar:

python scripts/eval_phase.py --phase phase9 --window SDL2 --observation-mode coords --delay 0.3 --save-success-state states/freeplay_start.state

Treinar freeplay a partir desse state:

python scripts/train_freeplay.py --state states/freeplay_start.state --timesteps 1000000 --observation-mode multi --n-envs 4 --vec-env subproc --start-method spawn --stagnation-steps 1200

Treino freeplay mais leve, sem tela na observacao:

python scripts/train_freeplay.py --state states/freeplay_start.state --timesteps 200000 --observation-mode ram --n-envs 4 --vec-env subproc --start-method spawn --stagnation-steps 1200

O freeplay novo usa por padrao a abordagem inspirada no PokemonRedExperiments v2:

--observation-mode multi
--action-set simple
--visited-radius 12
--blocked-move-penalty 0.02
--same-coord-stuck-steps 600

O action set simples usa noop, movimentos, A e B. START fica fora por padrao para
reduzir menus acidentais no comeco do freeplay.
Quando uma acao de movimento nao muda map/x/y, o freeplay aplica
--blocked-move-penalty. Quando o agente visita a mesma coordenada muitas vezes,
usa --same-coord-stuck-steps e --same-coord-stuck-penalty para reduzir politicas
travadas.

Teste curto, caso ainda queira usar o state da phase9:

python scripts/train_freeplay.py --state states/phase9_start.state --timesteps 200000 --n-envs 2 --vec-env subproc --start-method spawn --stagnation-steps 1200

Assistir freeplay:

python scripts/eval_freeplay.py --state states/freeplay_start.state --model models/pokemon_red_freeplay.zip --window SDL2 --delay 0.1

Assistir o freeplay com exploracao estocastica:

python scripts/eval_freeplay.py --state states/freeplay_start.state --model models/pokemon_red_freeplay.zip --window SDL2 --delay 0.05 --stochastic

Assistir e salvar trace CSV:

python scripts/eval_freeplay.py --state states/freeplay_start.state --model models/pokemon_red_freeplay.zip --window SDL2 --delay 0.05 --stochastic --trace-csv logs/freeplay_trace.csv

Resumir trace CSV:

python scripts/summarize_trace.py logs/freeplay_trace.csv

Avaliar o modelo antigo, treinado antes da memoria de exploracao:

python scripts/eval_freeplay.py --state states/freeplay_start.state --model models/pokemon_red_freeplay.zip --window SDL2 --delay 0.05 --action-set combo --legacy-observation --stochastic

Se interromper com q ou Ctrl+C, salva em:

models/pokemon_red_freeplay_interrompido.zip


11) Controle manual
-------------------

python scripts/manual_control.py --phase phase1 --window SDL2

python scripts/manual_control.py --phase phase2 --window SDL2

Comandos dentro do manual_control:

w = up
s = down
a = left
d = right
j = botao A
k = botao B
u = START
i = SELECT
. = noop
p = imprimir RAM
save states/phaseX_start.state = salvar state
q = sair

Exemplos:

ddddww
10j  (10 vezes A para interagir)
talk 10  (10 vezes B para dialogo)
wait 60


12) Significado dos argumentos mais usados
------------------------------------------

--phase
Escolhe qual fase usar. Exemplos: phase1, phase2.

--timesteps
Quantidade de passos de treino. Exemplo: --timesteps 20000.

--state
Escolhe o state inicial no freeplay. Exemplo: --state states/freeplay_start.state.

--observation-mode coords
Usa observacao simples [map_id, x, y]. E o modo inspirado no projeto v2.

--observation-mode ram
Usa map/x/y/event_count/party_count/in_battle normalizados. Use em fases com dialogo/menu.

--window null
Roda sem janela. Mais rapido para treinar.

--window SDL2
Abre a janela do PyBoy. Bom para assistir.

--delay
Pausa entre acoes na avaliacao. Exemplo: --delay 0.3.

--steps
Limite de passos na avaliacao ou teste. Exemplo: --steps 400.

--save-success-state
Salva o state quando a fase termina com sucesso.
Exemplo: --save-success-state states/phase2_start.state.

--save-wait-frames
Espera alguns frames antes de salvar o proximo state, para estabilizar transicoes.
Default atual: 90.

--action-frames
Frames segurando cada botao. Aumentar deixa cada toque mais longo.

--n-envs 1 --vec-env dummy
Forca um unico ambiente. Use quando quiser ver a tela no treino.

--stop-key-check-freq
Frequencia em timesteps para checar se q foi apertado durante o treino.
Default atual: 500.

Modelo interrompido
Se apertar q ou Ctrl+C durante o treino, salva em models/phaseX_interrompido.zip
em vez de sobrescrever models/phaseX_*.zip.

No freeplay, salva em models/pokemon_red_freeplay_interrompido.zip.

--resume
Continua um treino freeplay a partir de um modelo salvo.
Exemplo: --resume models/pokemon_red_freeplay_interrompido.zip.
Use --resume somente com modelo que tenha a mesma configuracao de observacao/acoes.
Modelo antigo do freeplay precisa de --action-set combo --legacy-observation.

--action-set simple
Usa noop, movimentos, A e B no freeplay. E o padrao novo.

--action-set combo
Usa o conjunto antigo com noop, select e combinacoes movimento+A/B.

--legacy-observation
Desliga a memoria de exploracao no freeplay para carregar modelos antigos.

--observation-mode coords
No freeplay, usa apenas [map_id, x, y]. Mais rapido, mas com pouca informacao.

--observation-mode ram
No freeplay, usa o vetor de RAM com posicao, eventos, party, HP e batalha.

--observation-mode multi
No freeplay, usa tela, RAM, memoria local de exploracao e acoes recentes.

--trace-csv
No eval_freeplay, salva um CSV com step, map/x/y, reward, acao, eventos e batalhas.

--visited-radius
Tamanho da memoria local de coordenadas visitadas que entra na observacao do freeplay.

--blocked-move-penalty
Penalidade quando uma acao de movimento nao muda map/x/y.

--same-coord-stuck-steps
Depois dessa quantidade de visitas na mesma coordenada, aplica penalidade de travamento.

--batch-size
Tamanho do batch do PPO. No modo v2 usamos 64.

--gamma
Fator de desconto do PPO. No modo v2 usamos 0.95.

--n-epochs
Epocas de otimizacao por update do PPO. No modo v2 usamos 10.

--learning-rate
Taxa de aprendizado. No modo v2 usamos 0.0003.

--ent-coef
Bonus de exploracao/entropia. No modo v2 usamos 0.0.


13) Fluxo recomendado para cada fase
------------------------------------

1. Conferir state:

python scripts/view_ram.py --phase phase1 --window null

2. Testar ambiente:

python scripts/test_env.py --phase phase1 --steps 40 --window null --observation-mode coords

3. Treinar:

python scripts/train_phase.py --phase phase1 --timesteps 20000 --observation-mode coords --window null

4. Assistir:

python scripts/eval_phase.py --phase phase1 --window SDL2 --observation-mode coords --delay 0.3

5. Salvar proxima fase:

python scripts/eval_phase.py --phase phase1 --window SDL2 --observation-mode coords --delay 0.3 --save-success-state states/phase2_start.state
